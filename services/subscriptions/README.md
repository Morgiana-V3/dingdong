# 叮咚 Node：服务器订阅服务

Node/Cordis 承接 Studio 的订阅插件，在当前叮咚中转服务器执行任务并投递消息。手机先查看任务列表，点击「添加任务」，选择服务器返回的插件，再配置内容与执行时间；右侧「所需账号」由已开启任务及统一推送的来源任务决定。

## 用 Docker 启动管理台

在安装了 Docker Engine 和 Compose v2（支持 `--wait`）的 Linux 服务器上，在仓库的 `services/subscriptions/` 运行部署脚本。也可以把这个服务目录单独复制到服务器上。已有部署请沿用原目录、Compose 项目名和数据卷。

```sh
sh deploy.sh
```

脚本构建镜像并等待订阅服务通过健康检查。首次运行优先引用同一仓库的 `../relay/.env`，其次引用独立部署的 `/opt/dingdong/.env`。其他位置可用 `DINGDONG_ENV_FILE=/绝对路径/中转.env sh deploy.sh` 指定。找不到已有配置时会从模板创建 `.env`。手机连接和推送使用中转服务的接收密钥、发送密钥及内部地址。两套服务的启动顺序和端口见 [完整部署说明](deploy/README.md)。

1. 在服务器的项目目录运行 `docker compose exec accounts cat /app/data/admin.key`，取得首次启动自动生成的网页管理密钥。
2. 在自己的电脑运行 `ssh -N -L 18890:127.0.0.1:18890 用户名@服务器`，保持这个终端打开。
3. 用电脑浏览器打开 <http://127.0.0.1:18890>，输入管理密钥。这个密钥仅用于管理网页。手机和中转各自沿用原有的接收、发送密钥。

### 管理台可做什么

- **订阅任务**：选择插件，填写插件字段和执行时间。支持搜索、查看运行记录、启停、立即运行和停止。统一推送可以选择已有来源任务。
- **平台账号**：查看订阅需要的账号，打开服务器上的平台登录页面，完成验证或退出账号。
- **AI 配置**：选择服务商，填写 API Key 后获取模型列表，也可手动填写模型 ID。平台实际可用性取决于账号、网络和模型是否支持任务所需的 Responses API 及工具调用。
- 手机和网页读取同一份任务配置。同一任务在另一端修改后，旧表单提交会收到版本冲突提示，重新打开编辑器即可读取新值。

### 推送卡片的 HTML 约定

服务端将预览标题、摘要写入 HTML 头部的 `og:title`、`og:description`，也同步写入消息的 `title`、`summary`。任务名称放在 `meta[name="dingdong:task"]`。有头图时，`meta[name="dingdong:cover"]` 的 `content` 是正文中对应 `img` 的元素 ID，可用 `getElementById` 取图，避免重复传输图片。无图时省略此项。旧消息以及接近大小上限、无法追加元数据的消息沿用客户端回退。

单帖使用原题。多帖默认选取前两个不同标题，可在网页任务编辑器选择 AI 配置并开启「AI 为多帖推送拟题和选图」。开启后每次新的多帖投递最多额外调用一次模型，只提供各帖标题、正文摘录与配图候选编号、图注。模型超时或返回无效结果时仍能正常推送。App 卡片要使用新版头图，需要客户端优先读取上述元数据。

Node 发送订阅消息前自动判断各帖的主要语言，外文使用任务关联的 AI 服务翻译。任务未关联时使用服务器配置列表中的第一项服务。中文帖原样送达。阅读页默认展示译文。每篇已翻译帖子在头部标签栏右侧显示「源」按钮，点按可查看原文，再点「译」切回译文。切换仅影响该帖的标题、正文和引用。原文和译文共用图片和原帖链接。没有可用模型、翻译失败或合并后的 HTML 超过大小限制时，发送原文。

## 已接入的 Studio 插件

| 插件 | 配置与执行能力 |
| --- | --- |
| B 站关注视频 | 指定 UP 主（可读取关注列表选择）、关键词、最多条数、可选 AI 简介整理；首次建立基线，之后只推送新视频 |
| 贴吧兴趣精选 | 1–5 个贴吧、全局/各吧筛选规则、相关度门槛、条数、配图、补充检索；使用 AI 工具读取与筛选原帖 |
| X 兴趣发现 | 兴趣规则、关注时间线、关键词检索、原帖读取、条数、配图、AI 工具筛选 |
| 小红书兴趣发现 | 兴趣规则、推荐流、关键词检索、原文读取、条数、配图、AI 工具筛选 |
| 统一推送 | 选择 1–8 个现有来源任务，合并投递；来源停止独立定时，部分来源失败保留其进度 |

源码和字段定义来自 `vendor/studio/`，`source-manifest.json` 记录原文件 SHA-256。Node 使用适配器替代 Electron 的子进程通信、浏览器和图片压缩。保留原插件的数据范围限制（首批/首屏、不是平台全部历史）、工具调用上限、超时和去重逻辑。

任务支持仅手动、固定间隔（1–10080 分钟）、每天定点（北京时间，最多 24 次）、启停、立即运行、停止、执行记录和内容变化检测。AI 在手机「订阅管理 → 更多 → AI 配置」管理，任务选择对应配置；需要支持 Responses API 与工具调用。密钥加密保存，不进入订阅快照。

## 手机登录流程

1. App 设置中连接当前中转服务器，保留原接收密钥；无需第二套 Node 地址。
2. 添加并开启任务。B 站可先留空 UP 主，登录后再编辑任务，从关注列表选择；未选择时不会执行。
3. 进入右侧「所需账号」，在官方页面自行登录，然后点击「授权给当前服务器」。
4. App 自动申请按平台隔离、10 分钟有效的一次性授权码；只经同主机 HTTPS 上传该平台所需 Cookie。
5. 服务器验证账号及内容读取成功后保存加密会话。仅检测到手机 Cookie 不等于服务器验证成功。
6. 手机登录不适用或需要网页验证时，可以通过 SSH 打开 Web 备用登录，选择平台并操作服务器浏览器。

贴吧读取公开内容，无需平台登录；AI 是它的必要依赖。X、小红书仍可能因服务器网络、平台风控或移动 WebView 限制而验证失败。不能把自动化夹具通过当作真实账号登录成功。

## 本地运行

需要 Node.js 22.19+、Chrome/Chromium。

```powershell
npm ci
npm start
```

打开 http://127.0.0.1:18890，首次管理密钥在 `data/admin.key`。默认只监听回环。`CHROMIUM_EXECUTABLE` 可指定 Chromium 路径；Windows 默认使用已安装 Chrome。

更新 Studio 复用代码：

```powershell
node scripts/sync-studio.mjs
npm run build
npm test
```

同步脚本默认读取叮咚仓库旁边的 `dingdong--studio/`，也可显式传入 Studio 路径。同步内容包括源码、样式与回归测试。`build/` 为生成文件。Cordis 管理运行时生命周期，原插件在 Node 子进程执行。

## 服务器部署与网络

按 `deploy/README.md` 部署。Node 在中转主机监听 127.0.0.1:18890；Nginx 仅公开 HTTPS 的 `/v1/accounts/` 与 `/v1/subscriptions`。管理网页及 `/api/` 仍通过 SSH 访问，不直接公开。

```sh
ssh -N -L 18890:127.0.0.1:18890 用户名@服务器
```

在电脑浏览器打开 http://127.0.0.1:18890，在「平台账号」中选择 B 站、X 或小红书进入官方页面。二维码、密码和验证码由用户操作。平台登录页通过服务器浏览器的截图与输入交互，不代表平台一定接受该浏览器环境。

`X_PROXY` 设置服务器可访问的 HTTP/HTTPS 代理（不带用户名密码），用于 X 浏览器、后台接口和配图。未设置时使用 `BROWSER_PROXY` 或直连；国内小红书保持直连。手机/电脑的 VPN 不会自动成为服务器的代理。凭据不能放入仓库，部署时使用环境配置。

会话分别保存为 AES-256-GCM 加密文件，共用数据卷内 `vault.key`；需要连同该密钥备份。修改服务器环境后通过 Compose 重建服务，不删除数据卷。

## 持久化与兼容

`GET /v1/subscriptions` 返回安装插件、任务、所需账号和脱敏 AI 配置。`POST /v1/subscriptions/commands` 使用 revision 检测并发编辑；支持任务保存、启停、删除、运行/停止和 AI 配置管理。运行状态不改变配置版本。运行异步返回，App 轮询执行结果。

`subscriptions.json` 原子写入。投递前保存消息与各来源待提交进度；中转确认接收后才提交进度。响应丢失/重启时重用完全相同的消息 ID 和正文，不重新采集。统一推送失败时也保留这份待发数据。执行取消不会丢弃已经保存的待发消息。单进程串行执行，不支持同一数据卷多个副本。

旧 `bilibili-following` 任务继续按原配置运行，列表标为旧版；新建只提供 Studio 插件。由于旧任务没有指定 UP 主，不自动猜测迁移范围。可新建指定 UP 主任务后自行停用旧任务。电脑 Studio 的任务可从「更多 → 电脑 Studio 管理」访问，不自动复制。

旧版 B 站插件声明 `digestSource`，允许与 Studio 任务一起选入统一推送。仍沿用原有 seen 记录，汇总投递成功后才提交去重进度；已有独立待发消息的来源需要先完成原投递。手机可在汇总编辑中直接配置新的插件来源，默认保存为暂停的手动任务，再自动选入汇总。启用汇总接管来源的调度，防止重复运行。

## 验证范围

`npm test` 包含原 Studio 平台/筛选/汇总回归，以及 Node 子进程真实通信、加密存储、平台授权隔离、配置冲突、待发消息恢复和 HTTP 认证测试。AI 与平台内容夹具不会调用真实模型或账号。

`npm run test:web` 使用本机 Chrome/Chromium 和临时数据目录，覆盖登录、任务增删改、手机接口读回、AI 配置、账号切换及窄屏布局。

2026-11-17 已在公网部署，使用现有 B 站账号实际读取关注列表并执行指定 UP 主基线任务，原任务配置保持不变。X、小红书真实账号与 AI 真实服务端执行需要对应登录/配置及可用网络，尚未据此验证。
